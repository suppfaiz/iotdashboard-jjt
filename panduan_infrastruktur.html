Bab 1

Gambaran Umum Sistem

Jamkrida Energy IoT Dashboard adalah platform pemantauan energi berbasis web yang dirancang untuk memonitor konsumsi listrik secara real-time dari sensor IoT (ESP32/PZEM) melalui protokol MQTT. Platform ini dibangun di atas framework Laravel 12 dan didistribusikan sebagai kontainer Docker untuk kemudahan deployment di VPS manapun.

Panduan Deployment VPS (Docker)

⚠️
Sebelum Memulai

Pastikan VPS sudah memiliki akses internet dan Anda login sebagai user dengan hak sudo. Semua prasyarat (Docker, PHP, Composer, Node.js) akan dipasang otomatis oleh skrip.

  • 1

    Clone Repositori Project

    $ git clone https://github.com/<username>/DashboardIOTbaru.git
    $ cd DashboardIOTbaru
  • 2

    Jalankan Script Installer

    Script otomatis: deteksi IP publik, install dependencies, compile aset, build container, migrasi database.

    $ chmod +x install.sh
    $ ./install.sh
  • 3

    Masukkan IP / Domain VPS

    Script akan mendeteksi IP publik secara otomatis. Tekan Enter untuk menerima, atau ketik IP/domain kustom.

    Enter your VPS Public IP Address or Domain [default: 123.45.67.89]:
  • 4

    Tunggu Proses Selesai (3-10 menit)

    =========================================================
    DEPLOYMENT SUCCESSFUL!
    =========================================================
    Web URL: http://<VPS_IP>
    Database GUI: http://<VPS_IP>:8082
    MQTT Broker: mqtt://<VPS_IP>:1883
    WebSocket Port: 8085
✅
Kredensial Default Aplikasi Web

Email: admin@admin.com  |  Password: password  — Ganti segera setelah login pertama!

Bab 5

Konfigurasi File .env

File .env adalah pusat konfigurasi seluruh sistem. Berikut parameter-parameter kunci yang perlu dikonfigurasi:

🔧
Konfigurasi Aplikasi Utama
# Identitas Aplikasi
APP_NAME="Jamkrida Energy Dashboard"
APP_ENV=production
APP_DEBUG=false
APP_URL=http://<IP_VPS>

# Database (MySQL)
DB_CONNECTION=mysql
DB_HOST=mysql
DB_PORT=3306
DB_DATABASE=dashboard_iot_baru
DB_USERNAME=root
DB_PASSWORD=<password_database_anda>
🔄
Konfigurasi WebSocket (Reverb)
BROADCAST_CONNECTION=reverb
REVERB_HOST="<IP_VPS>" # IP publik VPS Anda
REVERB_PORT=8085
REVERB_SCHEME=http
VITE_REVERB_HOST="<IP_VPS>" # harus sama dengan REVERB_HOST
VITE_REVERB_PORT=8085
📡
Konfigurasi MQTT
MQTT_HOST=mqtt # "mqtt" = Docker internal. Ganti ke IP eksternal jika broker berbeda
MQTT_PORT=1883
MQTT_USERNAME=jamkrida_sensor
MQTT_PASSWORD=<password_yang_di-generate>
💡
Tentang MQTT_HOST

Nilai mqtt adalah nama service Docker internal. Gunakan ini jika sistem berjalan dalam Docker. Jika menggunakan broker MQTT eksternal, ganti dengan IP/domain broker tersebut.

🔔
Konfigurasi Notifikasi Telegram (Opsional)
TELEGRAM_BOT_TOKEN=<token_dari_BotFather>
TELEGRAM_CHAT_ID=<chat_id_grup_atau_user>

Bab 7

Konfigurasi MQTT Broker

Sistem menggunakan Eclipse Mosquitto sebagai MQTT broker yang berjalan di dalam kontainer Docker. Autentikasi wajib diaktifkan untuk keamanan.

📄
File Konfigurasi Mosquitto
.docker/mosquitto.conf
persistence true
persistence_location /mosquitto/data/
log_dest file /mosquitto/log/mosquitto.log

listener 1883
allow_anonymous false # Wajib autentikasi
password_file /mosquitto/config/passwd
🔑
Manajemen Kredensial MQTT
Dibuat otomatis saat install.sh dijalankan
# Generate file passwd baru dengan password berbeda
$ docker run --rm -v "$(pwd)/.docker:/config" \
  eclipse-mosquitto:latest \
  mosquitto_passwd -c -b /config/passwd jamkrida_sensor <password_baru>

# Restart broker untuk terapkan perubahan
$ docker compose restart mqtt
🧪
Test Koneksi MQTT
# Subscribe ke semua topic (butuh mosquitto-clients)
$ mosquitto_sub -h <IP_VPS> -p 1883 -u jamkrida_sensor -P <password> -t "#" -v

# Publish test message
$ mosquitto_pub -h <IP_VPS> -p 1883 -u jamkrida_sensor -P <password> \
  -t "device/<device_key>/telemetry" \
  -m '{"voltage":220,"current":1.5,"power":330,"energy":5.0}'

Struktur topic yang dikenali sistem
TopicArahFungsi

Format Payload Telemetri (JSON)
Struktur data yang dikirim ESP32
{
  "voltage": 220.5, // Tegangan (Volt)
  "current": 1.52, // Arus (Ampere)
  "power": 334.76, // Daya aktif (Watt)
  "energy": 12.40, // Energi kumulatif (kWh)
  "frequency": 50.0, // Frekuensi (Hz)
  "pf": 0.98, // Power Factor
  "rssi": -62, // Kekuatan sinyal WiFi (dBm)
  "heap": 182340, // Free heap memory (bytes)
  "ip": "192.168.1.10" // IP lokal perangkat
}

Bab 12

Troubleshooting

❌
Dashboard tidak update real-time

Penyebab: WebSocket tidak terkoneksi, nilai REVERB_HOST salah atau port 8085 terblokir.

$ docker compose logs app | grep reverb
$ grep REVERB_HOST .env
$ sudo ufw allow 8085/tcp
❌
Data sensor tidak masuk ke dashboard

Penyebab: MQTT Worker tidak berjalan, kredensial MQTT salah, atau topic tidak sesuai.

$ docker compose logs -f app | grep mqtt

# Test publish manual
$ mosquitto_pub -h <VPS_IP> -p 1883 -u jamkrida_sensor -P <password> \
  -t "device/<device_key>/telemetry" \
  -m '{"voltage":220,"current":1.5,"power":330,"energy":5.0}'
❌
Error 500 saat akses web

Penyebab: Konfigurasi .env salah, cache belum di-clear, atau migrasi belum dijalankan.

$ docker compose exec app php artisan cache:clear
$ docker compose exec app php artisan config:cache
$ docker compose exec app tail -100 storage/logs/laravel.log
⚠️
Perangkat muncul offline padahal aktif

Sistem menandai perangkat sebagai offline jika tidak ada data masuk selama 5 menit. Periksa koneksi WiFi ESP32 dan pastikan topic MQTT yang digunakan sesuai dengan device key yang terdaftar.

💡
Tip: Monitor RSSI di Dashboard

Jika RSSI ESP32 menunjukkan nilai di bawah -80 dBm, pertimbangkan untuk memindahkan router lebih dekat atau menggunakan repeater WiFi.

Bab 14

Manajemen Perangkat & Kalibrasi

➕
Mendaftarkan Perangkat Baru
Alur registrasi perangkat ESP32
  • 1

    Buat Grup Lokasi

    Masuk ke Pengaturan → Grup, tambahkan grup berdasarkan lokasi (contoh: "Server Room", "Gedung A Lantai 2").

  • 2

    Daftarkan Perangkat

    Buka Perangkat → Tambah Perangkat. Isi nama, pilih grup, masukkan SSID dan password WiFi lokal ESP32.

  • 3

    Download Kode Arduino

    Sistem akan otomatis generate kode C++ siap pakai yang sudah berisi: device key, topic MQTT, WiFi credentials, dan alamat server. Copy & upload ke ESP32 via Arduino IDE.

  • 4

    Verifikasi Koneksi

    Setelah ESP32 dinyalakan, indikator status di dashboard akan berubah menjadi Online dalam beberapa detik. Data sensor langsung muncul secara real-time.

🔧
Kalibrasi Sensor
Menyesuaikan pembacaan PZEM-004T

Jika pembacaan sensor tidak sesuai dengan alat ukur referensi, gunakan faktor kalibrasi. Nilai baru akan diterapkan ke semua data masuk berikutnya secara real-time.

ParameterRentangDefaultKeterangan
Voltage Multiplier0.1 — 10.01.00Nilai tegangan dikali faktor ini. Contoh: 0.98 untuk kalibrasi -2%
Current Multiplier0.1 — 10.01.00Nilai arus dikali faktor ini. Power dihitung ulang dari V×I setelah kalibrasi
💡
Cara Menghitung Faktor Kalibrasi

Faktor = Nilai Referensi ÷ Nilai Terukur Sensor. Contoh: multimeter membaca 218V, sensor membaca 222V → faktor = 218 ÷ 222 = 0.982

💰
Budget Bulanan per Perangkat
Forecasting konsumsi individu

Setiap perangkat dapat diset batas konsumsi bulanan. Dashboard akan menghitung proyeksi akhir bulan berdasarkan rata-rata harian dan memberi peringatan jika melebihi budget.

FieldKeterangan
Budget kWh/bulanBatas energi maksimal per bulan dalam kWh
Budget Biaya/bulanBatas biaya maksimal per bulan dalam Rupiah
Proyeksi kWhEstimasi pemakaian akhir bulan = akumulasi + (rata-rata harian × sisa hari)
Proyeksi BiayaProyeksi kWh × tarif PLN aktif

Panduan Pemilihan & Cara Mengganti Broker MQTT
Pilihan 1: Broker MQTT Lokal (Docker Compose Mosquitto)

Gunakan opsi ini jika ingin data telemetri disimpan dalam jaringan lokal yang sama dengan VPS/Server tanpa bergantung koneksi internet luar.

  • MQTT Host: mqtt (jika Laravel berjalan di dalam Docker Compose yang sama) atau IP Publik VPS Anda.
  • MQTT Port: 1883
  • MQTT Username & Password: Masukkan kredensial lokal yang dibuat oleh install.sh (dapat dilihat di file host .env).
  • SSL/TLS Connection: Jangan centang (Disabled).
Pilihan 2: Broker Cloud (HiveMQ Cloud)

Gunakan opsi ini jika server berada di cloud terdistribusi dengan enkripsi tinggi tanpa membebani performa VPS lokal.

  • MQTT Host: Alamat host HiveMQ Anda (contoh: 25b7768b96d642e28fab356da906f103.s1.eu.hivemq.cloud).
  • MQTT Port: 8883 (wajib TLS).
  • MQTT Username & Password: Kredensial cluster yang Anda daftarkan di dashboard HiveMQ Cloud Anda.
  • SSL/TLS Connection: Centang (Enabled).
Pilihan 3: Enterprise Broker (EMQX Cluster)

Gunakan jika sistem Anda menskalakan hingga jutaan perangkat dan membutuhkan clustering failover performa tinggi.

  • MQTT Host: Domain atau IP Server EMQX Cluster Anda.
  • MQTT Port: 1883 (Non-TLS) atau 8883 (TLS).
  • MQTT Username & Password: Kredensial klien EMQX Anda.
  • SSL/TLS Connection: Sesuaikan dengan konfigurasi listener SSL/TLS di EMQX Dashboard.
⚠️
Langkah Penting Setelah Mengganti Broker

1. Simpan Pengaturan: Klik tombol Save Settings.
2. Upload Ulang ESP32: Kode Arduino ESP32 pada menu Devices -> Provisioning akan ter-generate ulang secara otomatis. Copy dan upload ulang kode tersebut ke microcontroller Anda.
3. Restart Worker: Di VPS, jalankan docker compose restart app agar background worker Laravel mendengarkan di broker yang baru.

Bab 16

Update Firmware OTA (Over-the-Air)

Fitur OTA memungkinkan pembaruan firmware ESP32 dari jarak jauh tanpa perlu menghubungkan kabel USB ke perangkat. Dashboard mengirim URL firmware melalui MQTT, dan ESP32 mengunduh serta mem-flash sendiri.

🔄
Alur Proses OTA Update
  • 1

    Compile Firmware Terbaru

    Di Arduino IDE, pilih menu Sketch → Export Compiled Binary. Akan menghasilkan file .bin di folder project.

  • 2

    Upload Firmware ke Dashboard

    Buka detail perangkat di dashboard → tab OTA Update → klik Upload Firmware (.bin). File disimpan di storage/app/public/firmwares/.

  • 3

    Kirim Perintah OTA

    Klik tombol Trigger OTA Update. Dashboard akan mengirim perintah via MQTT ke topic cmd/{device_id} berisi URL download firmware.

  • 4

    ESP32 Mengunduh & Flash Otomatis

    ESP32 menerima perintah, mengunduh file .bin dari URL, mem-flash ke partisi firmware baru, lalu restart otomatis dengan firmware terbaru. Progress ditampilkan di dashboard melalui WebSocket.

📋
Format Perintah OTA via MQTT
// Topic: cmd/{device_id}
{
  "cmd": "update_firmware",
  "url": "http://<VPS_IP>/storage/firmwares/firmware_dev_xxx_1234567890.bin"
}
📊
Monitoring Progress OTA (Real-time)

ESP32 mengirim laporan progress ke topic telemetry/ota_status/{device_id} yang kemudian di-broadcast ke dashboard via WebSocket.

// Progress update dari ESP32
{
  "progress": 75, // Persentase download
  "status": "downloading", // Status: downloading / flashing / done / error
  "message": "75% downloaded"
}
⚠️
Syarat OTA Berhasil

ESP32 harus dapat mengakses URL firmware (pastikan port 80 VPS terbuka). Firmware .bin harus di-compile untuk board yang sama. Proses OTA membutuhkan free heap memory > 50KB.

Dokumentasi Interaktif API (Scribe)

Untuk mempermudah integrasi pihak ketiga dan pengembangan perangkat baru, dashboard ini dilengkapi dengan dokumentasi API interaktif menggunakan Scribe dengan tema premium Stoplight Elements.

🌐
Akses Dokumentasi API
Dapat diakses langsung via browser

Dokumentasi API disajikan secara statis untuk performa maksimal dan 100% bebas dari kendala routing atau database Laravel:

  • 📍 URL Akses: http://<IP_VPS_ATAU_LOCALHOST>/api-docs/index.html
  • 🔗 Integrasi UI: Tombol API Docs pada bilah navigasi (Navbar) admin.
🛠️
Perintah Regenerasi Dokumentasi
Gunakan saat Anda memodifikasi atau menambah API baru

Jika Anda melakukan perubahan rute atau menambahkan controller API baru, jalankan perintah berikut untuk memperbarui dokumentasi:

# Jika berjalan secara lokal (Host PC/Mac)
$ php artisan scribe:generate

# Jika berjalan di lingkungan VPS (Docker Compose)
$ docker compose exec app php artisan scribe:generate

Perintah tersebut akan otomatis men-generate file HTML statis di folder public/api-docs/ beserta spesifikasi OpenAPI (openapi.yaml) dan Postman Collection (collection.json).
